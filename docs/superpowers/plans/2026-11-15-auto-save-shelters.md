# 避難場所データの自動保存 計画（2026-11-15 利用者 OK）

**Goal:** 電波があるときにアプリを開くと、避難場所データ（5県・約2.5MB）を裏で自動保存し、ボタンなしで電波なしの「近い避難場所」が使えるようにする。

## Global Constraints
- 既存の `saveShelters`（src/app/offline.ts）と専用キャッシュ・保存日の仕組みをそのまま使う。現在地・住所は保存しない（保存するのは5県すべての公開データ）。
- 自動保存の条件: `navigator.onLine`、`caches` あり、`navigator.connection?.saveData !== true`、まだ保存していない／`hasNewerData` が真／前回の自動保存が途中で止まった。
- 開始は表示が落ち着いてから（`requestIdleCallback` があればそれ、無ければ load 後 3 秒）。同時取得数は手動より少なく（2）。ユーザー操作（手動保存ボタン・削除）と同時に走らない（同じロック）。失敗しても画面にエラーを出さない（次回再開）。`navigator.storage.persist()` は手動保存と同じく呼ぶ。
- 利用者が「保存したデータを消す」を押したら自動保存を止める（`nankai-sim:shelters-auto-off`='1'。手動で保存し直したら解除）。
- データセーバー時・自動を止めた時は今のボタンのまま。
- 保存の欄の文言: 保存済み「✅ 電波がなくても使えます（YYYY年M月D日に自動で保存・N か所）」、保存中「電波がなくても使えるように、避難場所のデータを保存しています…（自動）」、未保存（自動対象外）は今のボタン。注意書き「一度も開いていないスマホでは使えません／iPhone はしばらく開かないと消えることがあります。ホーム画面に追加すると消えにくくなります」。
- 説明ページ（about）の保存の説明を更新。オフライン時の #near の「保存していません」文言は、自動対象の端末では「電波があるときに一度開くと自動で保存されます」を添える。
- テスト: 単体（自動保存を始める条件の純粋関数 `shouldAutoSave(...)`）、オフライン e2e（ページを開く→自動保存が終わる→オフラインで #near に一覧が出る／saveData 時は自動で保存しない／消すを押したら次回自動で保存しない）。
