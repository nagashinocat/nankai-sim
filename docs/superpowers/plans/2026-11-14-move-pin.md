# ピンを動かして調べ直す 実装計画

> branch `move-pin`。2026-11-14 利用者 OK。

**Goal:** 結果の地図で「📍 ピンを動かす」→ 地図中央の十字を合わせて「ここで調べ直す」で、建物の入力はそのままに新しい地点で全体を計算し直す。

## Global Constraints
- 日本語。計算（src/core）は変えない。既存の計算の入口（住所や現在地から結果を出す関数）をそのまま新しい地点で呼ぶ。
- 保存（Saved v4）は市町村名まで。ピン・住所・座標は保存しない（URL・ハッシュ・共有文にも入れない）。
- スマホ優先: ピンを直接ドラッグしない。十字を地図中央に固定（pointer-events: none）し、地図をパンして合わせる。ボタンは 44px 以上。
- こどもモードではボタンを出さない（結果は反映）。
- 「安心させすぎない」既存の文言はそのまま。

## Review Focus
1. 調べ直しの最中にもう一度押す・タブを替える・こども/おとなを替えたとき、古い計算の結果が後から上書きしない（世代番号などで捨てる）。
2. 範囲外の点・海の上の点（メッシュが無い）で既存どおりの表示になり、壊れない。
3. 「住所の位置にもどす」で元の結果に戻る（元の地点で計算し直してよい）。住所を入れ直して新しく調べたら、移動の状態はリセット。
4. 選んでいたタブ（想定ケース）と地図モード（揺れ/津波/両方）が残る。
5. 移動中に地図以外（再生アニメ・簡易地図など）が古い地点のまま残らない。

## Tasks
1. **地点を差し替えて再計算する入口**: main.ts / result.ts で、現在の入力（建物）と地点から結果を作る関数を、地点だけ変えて呼べるようにする。`moveState = { origin: LatLon(住所の地点, メモリだけ), current: LatLon }`。結果の上に「ピンの位置で計算しました（住所の位置から 北東へ約120m）」（minimap.ts の bearing/dir8/距離を使う、10m 単位）と「住所の位置にもどす」ボタン。単体テスト: 方向と距離の文、世代番号で古い結果を捨てる仕組み。
2. **地図の操作**（ui/map.ts / riskpanel）: 「📍 ピンを動かす」→ 編集モード: 十字（中央、太い線＋白縁、「ここを調べる」ラベル）、上部に「地図を動かして、十字を調べたい場所に合わせてください」、ボタン「ここで調べ直す」「やめる」。自宅の印は編集中は薄く。確定でモード終了→計算中表示→結果更新（地図は新しい地点が中心）。やめるで元どおり。
3. **テスト**: e2e（スタブ）: ピンを動かす→地図をパン（map.panBy 相当のドラッグ or キーボード）→調べ直す→自宅の市町村・やることマップ・矢印の文が変わる／もどすで戻る／範囲外に動かすと対応していない表示／保存に座標が無い／タブと地図モードが残る／こどもモードにボタンが無い／390px はみ出しなし。スクショを見る。HANDOFF に追記。
