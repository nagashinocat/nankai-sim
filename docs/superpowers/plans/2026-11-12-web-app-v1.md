# Webアプリ 第1版（三重県・ローカル動作） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 住所と建物情報を入れると、自宅の被害の目安（幅と代表値）、周辺1kmの推計、行動カードを表示する Web アプリを、三重県のデータでローカルに動かす。

**Architecture:** Vite + 素の TypeScript。計算は既存の `src/core/`（純粋関数）をそのまま使う。画面ごとに「表示用データを作る純粋関数（view model）」と「DOM に描く関数」を分け、前者を node:test で検証する。地図は Leaflet + 国土地理院の淡色地図タイル。データは `public/data/`（git 対象外）を同一オリジンから取得する。

**Tech Stack:** Vite 8 / TypeScript / Leaflet 1.9 / node:test（tsx）/ Playwright（スモークテスト1本）

**Spec:** `docs/superpowers/specs/2026-11-12-nankai-trough-sim-design.md`（§5 画面、§6 エラー、§7 プライバシー、§8 表現）

この計画の範囲: 第1版の画面（§5.1〜5.3, 5.5）とオフライン（§6）。範囲内に追加（2026-11-12 ユーザー承認）: 避難場所の検索（国土地理院 指定緊急避難場所データ 三重県, `data/raw/shelters/gsi_hinanbasho_24000_2.csv`）。範囲外: 半割れ・時間差・活断層タブ（第2版以降）、練習モード、公開（Task 6 で利用条件の確認が済むまで公開ビルドにハザードを含めない）。

## Global Constraints

- 最初に「これは耐震診断ではなく、統計的な目安です」を表示する（§5.2）
- 自宅の結果は幅（`estimateHome` の `collapse`/`half` の範囲）と代表値（`central`）で示す。数値は % で小数1桁
- 想定ケースは `L2`（最大クラス, Eq_champ）。表示名「最大クラス（国の想定）」
- 周辺は自宅から半径 1,000m のメッシュ（`meshesWithin(center, 1000)`）を `estimateArea`（代表曲線）で集計し「推計」と明記
- 住所は自前サーバーに送らない。住所→座標は国土地理院 `https://msearch.gsi.go.jp/address-search/AddressSearch?q=`（このことを説明ページに書く）
- 前回の結果は端末内（localStorage キー `nankai-sim:last`）にだけ保存し、削除ボタンで消せる
- 共有カードは初期状態で住所を含めない（市町名と結果だけ）
- データがないマスは「データなし」。推測で埋めない（§6）
- 想定エリア外（ハザードファイルが無い）→「南海トラフの想定では大きな揺れは想定されていません／この地域のデータは準備中です」
- 出典表示: 「内閣府 南海トラフの巨大地震モデル・被害想定手法検討会」ほか `public/data/manifest.json` の全データセット（説明ページ）
- 文字は基本 18px 以上、色だけに頼らずラベルを併記（§8）

- 避難場所: 出典「国土地理院 指定緊急避難場所データ（最終更新 2026-11-06）」。結果画面の避難セクションに次の注意を必ず表示する（国土地理院「ご利用上の注意」1〜3）:「データは最新でない場合や未掲載の場合があります。最新の指定状況は市町にご確認ください」「指定緊急避難場所（命を守るために緊急に逃げる場所）と指定避難所（一定期間滞在する施設）は別のものです」「指定緊急避難場所は災害の種類ごとに指定されています。地震・津波に対応しているかを確認してください」
- 徒歩時間は `src/core/evacuation.ts` の値（標準 1.0m/s、ゆっくり 0.5m/s、迂回係数 1.3）を使い「直線距離からの目安」と明記

## Review Focus

1. **住所が複数ヒット／0件** — 0件はピン指定の地図を出す。複数は候補リストから選ばせる（先頭を勝手に使わない）。Task 2 にテスト
2. **ハザードはあるが建物ストックが無いメッシュ（山林など）** — 自宅の結果は出し、周辺の推計は「建物データなし」。Task 3 にテスト
3. **構造・年代「わからない」** — 幅が大きく広がる。代表値は平均（`central`）で、注記「わからない項目があるため幅が広くなっています」を出す。Task 3 にテスト
4. **通信が切れた状態で開く** — 前回の結果を表示し、「前回の結果（日時）」と明記。Task 5 にテスト
5. **鉄骨・RC で階数未入力** — 幅の下側が高層の曲線になる。注記「階数を入れると幅が狭くなります」。Task 3 にテスト

### Task 3: 表示用データ（view model）

**Files:** Create `src/app/viewmodel.ts`; Test `tests/app/viewmodel.test.ts`

**Interfaces:**
- Consumes: `estimateHome`, `estimateArea`, `meshesWithin`, `latLonToMesh250`（`src/core`）、Task 1 の `DataSource`
- Produces:
  - `type HomeVM = { status: 'ok'; intensityLabel: string; collapse: { min: string; max: string; central: string }; half: {...同}; liquefaction: string | null; notes: string[] } | { status: 'nodata' } | { status: 'outside' }`
  - `homeViewModel(cell: HazardCell | null | 'outside', input: HomeInput): HomeVM`
  - `type AreaVM = { status: 'ok'; collapse: number; half: number; meshes: number } | { status: 'nostock' }`
  - `areaViewModel(cells: Record<string, HazardCell>, stock: Record<string, BuildingStock>, meshes: string[]): AreaVM`（棟数は 10 棟単位に丸める）
  - `intensityLabel(i: number): string` — 計測震度→「震度7」「震度6強」…（境界は 6.5/6.0/5.5/5.0/4.5/3.5）
  - `type EvacVM = { items: { name: string; distance: string; walkStandard: string; walkSlow: string; reach: 'ok' | 'tight' | 'no' | 'n/a' }[]; hazard: 'earthquake' | 'tsunami'; notices: string[] }`
  - `evacuationViewModel(origin: LatLon, shelters: Shelter[], cell: HazardCell | null): EvacVM[]` — 地震用（常に）と津波用（`tsunamiDepth` が数値のときだけ）の2リストまで、各5件。距離は「約{n}m」「約{n.n}km」、徒歩は「約{n}分」。notices は Global Constraints の3文
  - `formatPct(x: number): string` — `0.1234` → `"12.3%"`; 0.1% 未満 → `"0.1%未満"`
- 注記（`notes`）の文言（そのまま使う）:
  - 構造か年代が「わからない」: 「わからない項目があるため幅が広くなっています」
  - 鉄骨・RC で階数なし: 「階数を入れると幅が狭くなります」
  - 補強済み: 「耐震補強をした場合として、ひとつ新しい年代の基準で計算しています」
- 液状化: `settlementCm` が null → null; それ以外 → 「液状化で地盤が約{n}cm沈下するおそれ」（n は整数）
